# 실제 디스코드 연결에 필요한 설정

별도 사이트 화면은 http://127.0.0.1:4180/ 에서 볼 수 있습니다. 현재는 접수 준비 중이며 실제 신청은 전송되지 않습니다.

## 1. 새 사이트 배포

Vercel에 로그인한 뒤 GitHub `eoram00/aramportfolio` 저장소를 새 프로젝트로 가져옵니다. Root Directory는 `commission`, Framework Preset은 Other로 선택합니다. 기존 포트폴리오 프로젝트는 수정하지 않습니다.

## 2. 디스코드 봇

Discord Developer Portal에서 새 애플리케이션과 봇을 만듭니다. 서버에 신청 전용 카테고리를 준비합니다. 봇에는 채널 보기·채널 관리·메시지 보내기·링크 첨부·메시지 기록 보기 권한이 필요합니다. 관리자 전체 권한은 필요하지 않습니다.

## 3. Vercel 환경 변수

- APP_URL: 새로 배포한 신청 사이트의 https 주소
- DISCORD_CLIENT_ID: 애플리케이션 ID
- DISCORD_CLIENT_SECRET: OAuth2의 Client Secret
- DISCORD_BOT_TOKEN: Bot Token
- DISCORD_GUILD_ID: 연결할 서버 ID
- DISCORD_CATEGORY_ID: 신청 채널을 모을 카테고리 ID
- DISCORD_OWNER_IDS: 멘션을 받고 신청을 관리할 본인의 사용자 ID. 여러 명이면 쉼표로 구분
- SESSION_SECRET: 임의의 긴 비밀 문자열. 운영 중 임의로 변경하면 이전 신청 정보와 연결이 끊깁니다.

비밀값은 Vercel 환경 변수에 직접 입력하고 채팅·GitHub에 올리지 마세요. 서버·카테고리·사용자 ID는 디스코드 개발자 모드를 켠 뒤 우클릭으로 복사할 수 있습니다.

OAuth2 Redirects에는 `새사이트주소/api/auth/callback`을 등록한 뒤 재배포합니다.

## 4. 포트폴리오 버튼 연결

새 사이트 주소가 확정되면 `site/data/commission.json`의 url에 그 주소를 넣습니다. 로컬 포트폴리오의 신청 버튼은 4180 미리보기로 연결됩니다. 실제 배포에서는 주소가 확정되기 전까지 숨겨져 있습니다.

## 5. 관리 흐름

신청 접수 → 비공개 채널 생성 → 본인 멘션과 신청 내용 → ‘신청 관리 · 연락하기’ 버튼 → 관리자 로그인 → 수락·거부·취소·메시지.

신청자도 로그인해서 본인 신청과 대화를 확인하고 검토 대기 신청을 취소할 수 있습니다. 신청자가 서버에 가입할 필요는 없습니다. DM이 막혀도 답변은 사이트 신청 내역에 남습니다. 디스코드 채널에 사람이 직접 쓴 메시지는 사이트로 전달되지 않으므로 관리 화면에서 답변해주세요.

실제 토큰으로 로그인·채널 생성·멘션·메시지·취소까지 한 번 확인한 뒤 접수를 시작하세요.
