## 실제 접수 개시 전 필요한 확인
`privacy-settings.json`은 검토본이며 reviewed=false입니다. OAuth와 봇 비밀값이 채워져도 이 상태에서는 로그인·신청이 열리지 않습니다.
1. 공개 운영자 표기가 실제 운영 주체와 일치하는지 확인합니다. 사업자로 운영한다면 실제 사업자 정보·책임자 표기를 보완합니다.
2. Discord를 신청 정보 저장에 사용하는 관계의 법적 성격(수탁/제공), 적용 약관·계약 및 국외 이전 근거를 검토합니다. 제공자 정책만으로 이 사이트의 처리 적법성이 보장되지는 않습니다.
3. Vercel 프로젝트의 Functions 실행 지역, 실제 로그 항목·보관 기간·삭제 절차, 하위 처리자와 이전 국가를 확인하고 설정 파일에 기재합니다. 예측한 국가나 보관 기간을 넣지 않습니다.
4. 각 제공자의 연락처, 국가, 이전 항목·목적·시점·방법·보관 기간을 확인한 후 transfers[].verified=true를 설정합니다.
5. 쿠키, 선택 항목, 별도 계약·거래 기록의 보관 여부 등 안내가 실제 운영과 일치하는지 확인한 후 reviewed=true로 확정하고 문서 버전을 갱신합니다. 이는 운영 확인 스위치이며 법률 인증이 아닙니다.
6. 충분히 긴 임의의 CRON_SECRET을 Vercel Production 환경 변수에 저장합니다. 채팅·저장소에 올리지 않습니다. 봇/OAuth/SESSION_SECRET도 별도로 필요합니다.
7. Production에 재배포한 뒤 Vercel Cron Jobs 실행을 확인합니다. 스케줄은 하루 한 번 18:00 UTC(한국 시간 다음 날 03시대)이며 Hobby 플랜의 실행 시각에는 오차가 있습니다.

## 정리 실패 대응
- 인증: /api/privacy/cleanup은 CRON_SECRET과 일치하는 Bearer 인증만 허용합니다.
- 한 실행에서 최대 25건, 약 40초 예산으로 정리합니다. 남은 건 또는 실패가 있으면 HTTP 503 및 건수만 반환합니다. 개인정보·토큰을 로그에 출력하지 않습니다.
- 운영자는 Cron 실행 실패/503/미실행을 매일 확인하고 인증된 재실행 또는 Discord에서 직접 삭제합니다. 자동 장애 알림까지 구현된 것은 아닙니다.
- 삭제는 운영 중인 Discord 게시글을 제거합니다. 제공자 백업·보안 로그 삭제 완료를 보장하지 않으며 실제 제공자 절차로 대응해야 합니다.
- SESSION_SECRET을 임의로 교체하면 이전 신청의 서명을 읽지 못하여 자동 삭제 대상에서 빠질 수 있습니다. 교체 전 기존 게시글을 정리하거나 별도 이관 절차를 마련하세요.
- 관리자가 게시글 이름을 변경하면 서명 기반 자동 정리에서 제외될 수 있습니다. 자동 생성 이름은 바꾸지 않습니다.
- 법정 보존 대상인 계약·거래 증빙은 이 상담 저장소에 섞지 말고 별도 적법한 절차로 보관합니다. 사이트는 결제를 받지 않습니다.
